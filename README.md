# Hold My Torch!

轻量的 Minecraft **纯客户端输入防手滑 Mod**。英文名：**Hold My Torch!**；中文名未定。开源许可证：**GNU AGPLv3，AGPL-3.0-only**。

目前为 **0.1.3 预览版**。仅提供以下两个独立版本，不混装：

| Minecraft | 加载器 | Java |
| --- | --- | --- |
| 1.20.1 | Forge 47.x | 17 |
| 1.21.1 | NeoForge 21.1.x | 21 |

只将对应 JAR 放进**客户端**的 `mods` 目录。服务器不需要安装，不注册网络通道、物品、方块或服务端功能。构建说明见 [BUILD.md](BUILD.md)。未承诺上述范围以外的 Minecraft 或加载器版本。

## 功能

- **高亮物品防误放**：游玩时手持 `BlockItem`，且识别亮度**严格大于 12** 时按当前操作的手过滤使用输入。默认只保护副手；“保护主手高亮物品”开关默认关闭，打开后也保护主手。默认识别火把、灯笼等，默认不保护亮度 10 的灵魂火把。阈值可调为 0–15。
- **防误丢弃**：过滤 Minecraft 注册的“丢弃”快捷键，重新绑定后仍生效。确认后由原版执行，Ctrl 的整组丢弃语义也交给原版；**按确认生效时 Ctrl 是否按住决定单个 / 整组**。不保护背包或其他 GUI 内的丢弃、拖动操作。
- **自定义快捷键**：从游戏已注册的快捷键列表搜索并添加规则，每条独立配置。规则使用绑定名称保存，更改实际键位后仍适用。自定义同名规则优先于内置模块；例如为“使用物品”添加通用规则，会保护所有使用操作，包括开门。

每个模块 / 规则独立选择一种确认方式：

1. **长按**：默认 **500 ms**，范围 100–10000 ms。
2. **双击**：默认窗口 **300 ms**，范围 100–2000 ms，按两次之间必须松开；系统自动重复不算双击。
3. **独立确认键**：按住操作键时同时按住确认键，也可以先按住确认键再按操作键。默认左 Alt，可录入其他键盘键或鼠标键，包括鼠标侧键。松开后需开启下一次操作手势；一次手势只产生一次点击。

确认后，持续按住的操作保留原版持续行为，例如连续放置；丢弃等消费点击的操作每次确认只产生一次点击。切换手持物品、键位、界面或失去窗口焦点会使已有确认失效。

触发保护时，右下角显示约 2 秒的字幕提示，说明被拦截的操作及当前确认方式。同一次按住只提示一次；确认成功、打开界面或失去焦点后清除。主手使用优先、需要先松开再重新按下等情况会显示对应原因；开启原版声音字幕时提示会上移。

## 游戏内配置

打开 **Mods → Hold My Torch! → Config / 配置**，进入原生 Client Config 图形菜单，无需 Cloth Config、YACL 或其他配置 UI Mod。

- 每项旁边都有“重置”，`*` 表示与默认值不同。
- 高亮模块重置也会重置主手保护开关（默认关闭）、亮度阈值和动态光源适配开关。
- 确认方式下方只显示该方式相关的参数；切换方式可编辑其他参数，已有设置会保留。
- 自定义模块重置会移除全部自定义规则；单条规则可独立重置或移除。
- “恢复全部默认设置”有二次确认。
- 在子页面点击返回，回到根页面后“保存并关闭”写入 `config/holdmytorch-client.json`。根页面 Esc 同样保存。设置只存在客户端，不同步给服务器。
- 数字变红表示无效，不应用该输入，保留最后一个有效值。确认键录入时 Esc 取消录入。
- 提供 `en_us` 和 `zh_cn` 文本。菜单支持搜索和分页；切换型快捷键显示不支持提示。

## 输入层实现与兼容边界

本 Mod **过滤输入，不在放置事件里撤销物品，也不伪造库存或修改数据包**。丢弃和自定义规则过滤 `KeyMapping.isDown()` / `consumeClick()`；高亮放置保护过滤加载器的 `InputEvent.InteractionKeyMappingTriggered`，在当前手开始交互、使用物品和发包之前决定是否放行。`KeyMapping.setDown()` 记录实际按下 / 松开边沿，因此重新绑定使用键后仍生效。

右键同时承担交互和放置，因此不能盲目吞掉所有右键。非潜行时，对一组已知原版交互目标（木门、活板门、栅栏门、箱子、木桶、潜影盒、熔炉、常见工作台、按钮、拉杆等）保留直接交互。铁门 / 铁活板门仍按可能放置处理。潜行时，高亮物品所在手的使用输入按放置处理。**开启主手保护且主手拿着高亮物品时，其他 Mod 的方块若覆写了标准右键交互方法（包括继承的实现），同样直接放行**：Forge 识别 `use`，NeoForge 识别 `useWithoutItem` / `useItemOn`，因此拿着火把也能直接操作这类机器、容器和开关。检测按运行时方法签名进行并缓存，不要求额外兼容依赖，也不会试调用交互函数。未实现这些方法的 Mod 方块仍要求确认。自定义高亮 BlockItem 面向原版方块时仍保守要求确认。

**副手拿火把、主手使用物品时**，主手只要不是受保护的高亮放置物品，就按游戏原有流程正常处理，不要求物品必须提供使用动画，也不区分原版或 Mod 来源。主手的吃喝、蓄力、举盾、望远镜、抛竿、工具及其他正常右键操作不会被副手火把一起拦住。只有游戏真正轮到处理副手时，才检查副手的保护规则。

为避免吃饱、没有弹药、冷却等失败条件把持续使用输入变成放置：当主手物品具有食物属性，或声明了吃喝、蓄力、防御等标准使用动作（`UseAnim` 不为 `NONE`）时，直接阻止副手高亮物品的回退使用，长按也不会改为放置。此时若要有意放置副手火把，需要换下主手的这类物品。主手是普通工具等物品时，副手火把仍可用配置的长按、双击或确认键方式放置。主手物品用完或切换后，已有火把确认失效，须松开再重新按下；不会沿用吃东西期间的长按时间。

放置在地上供右键食用的 Mod 食物方块按前述方块交互方法识别。普通主手交互先正常执行；若主手没有处理，副手高亮物品仍须确认，不因为目标可能可交互就绕过保护。主手保护默认关闭，因此主手普通方块和高亮方块均可按原版直接放置；开启该开关后，仅主手高亮物品需要确认。主手拿火把、副手拿食物仍遵循游戏原有的主副手处理顺序，不自动交换物品。

以下限制必须在使用前理解：

- 没有食物属性且声明 `UseAnim.NONE` 的特殊物品仍可正常执行主手操作；若其返回未处理，副手高亮使用进入通常的确认流程。客户端无法仅凭任意自定义物品的方法推断玩家是否希望改用另一只手。
- 主手高亮物品对交互方块的直接放行例外仍将该手的操作交给游戏和其他 Mod。交互方法可能因物品、点击面、权限或方块状态而返回未处理，随后游戏仍可能尝试用同一只手放置火把；仅凭方法存在不能保证每次都成功交互。仅通过事件监听器实现、没有覆写标准方法的交互暂不能自动识别。服务器插件、其他 Mod 或修改后的原版交互也可改变行为；客户端无法推断所有服务端结果，直接交互例外不构成绝对防放置保证。
- 自动识别目前限于 `BlockItem`。使用特殊 `Item.use()` 放置的物品、流体桶、实体生成物品等尚未纳入。默认方块状态的亮度可能无法代表所有 NBT / 组件或特定放置状态。
- 默认使用方块自身亮度作为保底。可选适配器尝试读取 RyoamicLights、LambDynamicLights 旧兼容静态接口，以及公开的 OptiFine 物品亮度接口；取与方块亮度的较大值。没有这些 Mod 也能运行。这是**可选接口适配**，不代表所有版本或动态光源 Mod 已验证兼容，也不读取着色器最终画面亮度。水敏感物品按干燥亮度保护，以避免落水时意外取消保护。
- 自定义规则适用于通过标准 `KeyMapping` 读取的游玩操作。直接监听 GLFW / 原始键鼠事件、直接调用动作或发包的 Mod，可绕过这里的过滤；覆写读取方法的快捷键子类也无法保证。原版 `ToggleKeyMapping`（例如切换式潜行 / 疾跑）目前不支持，配置列表禁止添加，也不会声称已经保护。
- 不主动拦截 GUI、聊天或系统快捷键；不改变多个规则共用同一实体按键时原有的按键冲突。确认键与操作键选成同一键会失去额外确认的意义。

## 源码与许可证
